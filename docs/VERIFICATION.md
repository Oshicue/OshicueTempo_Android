# 验证记录（Android 移植）

验证日期：2026-10-17（Asia/Shanghai）。环境：Android Studio JBR 25、AGP 9.4.1、Gradle 9.8.1、Android SDK Platform 37（Android 17）、Medium Phone API 37.0 模拟器（1080 × 2400，420 dpi）。

## 单元测试（16 项全部通过）

`./gradlew :app:testDebugUnitTest`：`TempoCoreTests` 8 项 + `TempoStoreTests` 8 项，覆盖与 iOS 测试相同的场景：

- 截止时间运算、归零钳制、暂停冻结、继续生成新截止时间、过期暂停直接结束。
- 券数与单券秒数边界（-1、0、1000、Int.MAX）、24 小时上限、999 × 1 秒。
- 团体名称与颜色规范化（去空白、`#ff688d` → `FF688D`）、非法颜色、空成员。
- 快照 JSON 编解码（含运行中与暂停轮次）、孤儿轮次与冲突字段拒绝、与 Swift `JSONEncoder`（`.sortedKeys` + `.prettyPrinted` + `millisecondsSince1970`）逐字节一致的输出。
- 持久化恢复（运行中 + 暂停）、编辑团体冻结进行中轮次、跨团体独立计时且只触发一次完成回调、删除成员/团体只取消相关轮次、非法启动保留原轮次、损坏文件保留且不再写入、写入失败不提交新数据。

## 模拟器功能验证（截图逐项检查）

- **主计时板**：品牌字样（Unbounded）、LUMINA 四人同屏、代表色圆点、进度环、四人独立卡片；浅色与深色两套外观均检查；中文（简体）与英语界面均检查，与 iOS 版逐像素级对照一致（成员代表色对比度补偿在两种外观下输出同一颜色）。
- **券数输入**：点击时钟或「输入券数」打开底部弹窗并自动弹出数字键盘；输入 2 张显示 `30 秒 / 张 × 2 张` 与 `01:00`；确认后立即开始。
- **运行/暂停/继续/重置**：运行中 LIVE 徽标、进度环随时间收缩、暂停后数字冻结显示「已暂停」、继续恢复、重置弹出「重置 X 的本轮计时？」确认框。
- **到时状态**：前台结束时显示 `00:00 / 时间到`，卡片淡化，按钮变为「下一轮」；不重播过期声音。
- **第五位成员与翻页**：编辑团体添加成员（补全姓名后保存）→ 列表显示「5 位成员」→ 主页出现两页指示器与左右箭头，第二页显示第五位成员与三个空位。
- **团体管理**：列表、当前团体勾选、添加团体、删除确认（含进行中计时数量提示）、编辑入口。
- **声音与提醒**：内置四种提示音及试听、导入状态、通知权限状态（首次开始计时自动弹出权限请求；允许后显示「已允许通知」）。
- **录音导入（SAF）**：从系统文件选择器导入 `test-recording.wav`（1.6 秒）成功，弹出「录音已添加」，列表显示「已导入 · 1.6 秒」。应用私有目录生成 `Sounds/import-<uuid>.wav` 与 `tempo-imports.json`，系统通知目录生成 MediaStore 副本并记录 `mediaUri`。
- **后台通知**：计时中按 Home 离开，到点后通知出现在通知栏：标题「凛 · 本轮结束」（按成员语言正确插值）、正文本地化、走 `tempo-bell` 渠道的自定义提示音（`dumpsys notification` 确认 `mSound=android.resource://…`）。点按通知返回 App，过期轮次显示「时间到」。
- **通知渠道**：`tempo-chime / pulse / bell / arcade / default` 五个渠道位于「Oshicue Tempo」分组，名称与提示音一一对应，均设定自定义声音资源。
- **持久化**：结束进程后重新打开，团体、成员、轮次与选择状态完整恢复。
- **精确闹钟**：`dumpsys alarm` 确认 `ELAPSED_WAKEUP` 精确闹钟（`window=0`）按截止时间排定；接收器在读取状态后对已取消/已暂停的轮次跳过提醒。

## 发布包验证

- `assembleRelease` 开启 R8 与资源收缩后为 3.6 MB，签名校验通过，安装到模拟器后复测：主界面渲染、计时开始/到时提示音、通知权限申请、后台通知投递均正常。
- 发布构建曾暴露资源收缩导致字符串式 `getIdentifier` 找不到内置音效的问题；已改为编译期 `R.raw` 直接引用（`TempoAudio.builtInResource`），并在发布包上复测通过。

## 平台适配说明（与 iOS 的行为差异）

- 后台提醒使用 AlarmManager 精确闹钟 + 通知渠道（iOS 为本地通知）；渠道声音在创建后不可修改，导入录音因此额外复制到 MediaStore 以支持系统播放。
- 精确闹钟被系统撤销时退化为不精确提醒（仍会触发，可能延迟）；Android 14+ 计时类应用声明 `USE_EXACT_ALARM` 自动获得精确权限。
- 导入使用系统文件选择器（SAF）代替 iOS 文件导入面板，帮助文案已改写为 Android 流程。
- 应用语言使用系统「应用语言」设置（Android 13+，`localeConfig`）代替 iOS 的 App 语言设置。

## 验证范围

未在实体设备上验收外放音量、耳机/蓝牙输出与勿扰模式下的通知表现；模拟器为无音频模式，播放路径以状态、日志与渠道配置验证，未做听感验收。厂商 ROM 的精确闹钟与通知渠道限制需真机复核。
